# Digital Human Video

Turn a topic and a short Chinese line into a topic-matched animated-avatar video. Choose the route the user requested; never switch between Muse and local inference silently. For a requested Muse run, follow the one-pass path below. It is designed to use one image generation, one Muse submission, and one lightweight quality pass.

## Fast path: ImageGen → Muse → local output

1. **Intake once.** Use the topic and exact Chinese narration from the request. Keep each spoken line to 20 Unicode grapheme clusters, including punctuation. If topic or narration is missing, ask only for the missing item; do not invent production copy. Default to a warm, natural female Mandarin voice unless the user specified another voice.
2. **Choose or make one avatar.** If the user wants the same character or series and a suitable approved local avatar exists, reuse it. If the requested image is already in the selected Muse chat, refer to that in-chat asset; a Codex/ChatGPT or project-folder image is not automatically visible to Muse. Otherwise use the built-in ImageGen tool once to make one original character that fits the topic and audience. For this project's default, use a polished 3D cartoon full-body presenter with one visible topic cue in the outfit, palette, or background—not a collection of props. For Muse's usual landscape output, compose in 16:9 with the character filling about 70–80% of the frame height and safe head/feet margins; obey another requested aspect ratio. Keep face unobscured, eyes toward camera, relaxed closed lips, hands visible and slightly separated from the torso, simple light background, and no text, logo, watermark, extra people, or extreme pose. Keep identity traits stable across a series. Do not generate multiple variants unless asked.
3. **Inspect and stage the image.** Check topic fit, visible face/hands/feet, and animation-friendly pose once. Use the generated file path returned by ImageGen; copy the selected image to a unique project location such as `outputs/avatars/<topic-slug>/avatar.png` (or the user's named path) before uploading. Do not overwrite an existing avatar. In this repo `outputs/` is git-ignored; keep generated images and media out of commits.
4. **Send image and prompt together.** Use `mcp__cua_repl.js` on the user's explicitly selected Chrome tab. Confirm it is the intended Muse chat and leave unrelated tabs untouched. Attach only the selected avatar, then submit one concise prompt with the topic, exact narration, voice, and constraints: preserve the attached character; use a locked camera and the requested framing; animate the whole face with natural modest mouth motion, steady gaze, slow subtle blinks, and one small topic-appropriate hand gesture; avoid facial/body redesign, exaggerated mouth or eyebrows, wandering eyes, extra fingers, cuts, or zoom. Ask for one short continuous video with audio in the MP4 and a separate MP3 when supported, with no added intro/outro or long silent padding. Do not demand frame-exact lip sync unless the user asks for it.
5. **Wait on that single task.** Watch Muse's visible task status using fresh UI state; do not refresh, resend, or start a duplicate. Check after about 10–15 seconds, then every 20–30 seconds while it is working; give a concise progress update if the wait exceeds a minute. Continue until delivered or a definite failure. A disconnected/offline label alone is not a blocker if the user explicitly said to use the composer anyway. Stop and ask if Muse requires a purchase, plan upgrade, legal acceptance, new permission, or an unapproved external action.
6. **Collect for review.** Download the delivered MP4 and separate MP3 through Muse's visible download controls to the browser's local Downloads folder or a temporary review folder. Verify they exist and are non-empty; do not overwrite an existing file.
7. **Run one lightweight quality pass.** Use `ffprobe` to confirm duration, resolution, video/audio streams, and MP3 duration. Make a 4–6-frame contact sheet and inspect identity, full-body framing, mouth/eye motion, gesture, camera stability, and obvious distortions. Verify the spoken line through available playback or a reliable transcript; if neither is available, say audio was structurally checked but not independently heard. Do not claim exact lip sync unless it was checked. If output is missing or materially flawed, keep the staged source, report the defect, and ask before spending credits on another generation.
8. **Save verified outputs.** After QA, copy the selected avatar, MP4, and MP3 into a unique folder such as `outputs/muse-<date>-<topic-slug>/` or the user's named destination. Keep generated/private files out of commits. Link the saved paths, state duration/resolution and any limits (for example, mouth motion is natural but not frame-exact), and label Muse work as external/browser-generated, not local inference.

### Reusable Muse prompt shape

Keep the actual prompt compact and fill in the user's values:

> Use the attached image as the exact character reference. Topic: **[topic]**. Say exactly in Mandarin: “**[verbatim line]**”, with a warm natural female voice at a clear moderate pace. Make one short continuous full-body speaking clip: locked camera, steady eye contact, natural small mouth motion, subtle slow facial movement, and one small open-palm gesture; preserve the face, hair, clothing, and topic cue. No extra words, cuts, zoom, redesign, exaggerated expressions, wandering eyes, or extra fingers. Return one downloadable MP4 with audio and a separate MP3 if available. One generation only.

For a same-topic series, cache and reuse the selected avatar instead of regenerating it. For a genuinely new topic or character, make a new image once; do not create a new image merely because the narration changes.

## Browser and data boundaries

The Muse route sends the selected image and requested text to an external provider. Only a user request for this ImageGen→Muse workflow authorizes sending the image generated/selected for this run and its narration—not other portraits, voice recordings, credentials, project files, or conversation history. If uploading a local image, identify that exact file and destination. If Chrome's file chooser fails, do not weaken extension permissions or silently substitute an in-chat avatar. Tell the user: “To enable file upload, open `chrome://extensions`, click **Details** under the ChatGPT browser extension, and enable **Allow access to file URLs**.” See the [Chrome file-upload instructions](https://developers.openai.com/codex/app/chrome-extension#upload-files). Never change the permission yourself. Do not accept legal terms, buy credits, or upgrade plans without action-time approval; if the visible cost is not covered by the user's request or included balance, stop and ask.

## Local pipeline (only when requested)

Before setup, read the project README, `.env.example`, and third-party notices. Confirm Apple Silicon/macOS before recommending MLX/MPS, and use the documented Qwen3-TTS/MLX path for local Chinese speech. Run `scripts/demo_fake.sh` before installing model weights; for a real render, follow the pinned setup and checksum scripts, keep MuseTalk and LivePortrait in separate environments, and run only one render at a time on a 24GB Mac. Reuse the avatar preprocessing cache for a stable avatar; choose the cached LivePortrait loop when speech timing need not match the mouth, noting it is not waveform-driven. Choose MuseTalk only for requested approximate audio-driven lip motion and inspect cartoon faces for deformation. Keep the unauthenticated FastAPI service and MuseTalk sidecar on `127.0.0.1`. Until the detector licensing issue is resolved, use LivePortrait only with `--noncommercial-research` for genuinely non-commercial work. Report whether results were verified on real hardware or only through the fake/simulated path. If the user reports local video inference freezes the computer, stop and do not retry unless explicitly reauthorized.

## Release and commercial checks

Before packaging, inspect third-party notices and model terms. LivePortrait's license flags InsightFace detection models as non-commercial research only; commercial users must replace them with a commercially licensed detector or obtain permission. Never describe that setup as commercially cleared until the detector issue is resolved. For Muse, separately review provider terms for uploaded images/text, generated audio/video, commercial use, retention, and export. `BUYER-LICENSE.txt` grants only the purchasing customer use and private modification; it prohibits sharing, resale, and redistribution and must be included with every paid package. It does not grant rights to models, code, inputs, identities, voices, or outputs.
