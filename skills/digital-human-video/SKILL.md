# Digital Human Video

Turn the user's topic, script, and production preferences into a speaking-avatar video. This skill uses ImageGen for character art, Muse through computer-use for silent video and separate speech audio, and local FFmpeg only for composition and media checks; it does not provide local TTS or video inference. Style, framing, duration, language, voice, tone, movement, background, captions, and output format are per-run choices—not fixed presets. Honor explicit preferences; ask only when a missing choice materially changes the result. Otherwise use the least surprising choice for the context and say what you assumed: for slide overlays, prefer transparency if supported; for a self-contained scene, use a restrained topic-appropriate background. Never assume a solid-color backdrop is transparency. Generate character art, silent video, and spoken audio as separate assets, then combine them locally with FFmpeg before QA.

## Resolve the run requirements

1. **Intake once.** Capture the topic, exact narration, audience/use, visual style or reference and mood/palette, framing/aspect ratio, explicit target duration and ending behavior if provided, language/accent/voice/tone/emotion/pace, facial and body motion/gestures/camera, background policy, captions/on-screen text, target resolution/frame rate, output format, and destination app when provided. These are options, not a mandatory questionnaire: ask only for missing information that materially affects the result. Preserve supplied copy verbatim; do not invent or rewrite narration. If no duration is specified, derive it from the exact narration and requested pace: prefer measured generated-audio duration when available, otherwise estimate from language-appropriate spoken units and punctuation pauses. Do not ask for a duration merely because it is omitted, or rewrite/speed up speech to fit a preset. Ask how to resolve an explicit duration that conflicts with natural delivery. Check Muse's actual limits when needed; if the requested timing cannot fit the text naturally, ask before rewriting or speeding up speech.
2. **Choose or make one avatar.** Reuse an approved existing avatar when the user wants continuity and it fits the request; an image in Muse chat may be reused there, but a local or Codex image is not automatically visible to Muse. Otherwise use ImageGen once to create an original character suited to the topic, requested art style, intended crop, and animation. Do not force cartoon, full-body, a particular gender, or a fixed aspect ratio. Keep identity stable across a requested series, with a clear unobstructed face and limbs suited to the requested movement. Include or omit scenery, shadows, text, logos, and topic motifs according to the request; do not make unrequested variants.
3. **Verify and stage the image.** Check the requested style, topic fit, crop, identity, and visible face/body details. When transparent output is requested, verify the PNG has actual alpha pixels—not a checkerboard or an image depicting transparency. If transparency is unavailable, ask before background removal or accepting an opaque substitute. Save the selected image to a unique local path such as `outputs/avatars/<topic-slug>/avatar.png`; do not overwrite an existing avatar.
4. **Generate the silent video in Muse.** Use `mcp__cua_repl.js` on the user's explicitly selected Chrome tab. Confirm it is the intended Muse chat and leave unrelated tabs untouched. Attach only the selected avatar. Request the specified style, framing, background, and motion; if Muse exposes a duration control, use the inferred duration from the exact line and requested pace, or the user's explicit target; describe facial expression, gaze, mouth movement, blink rate, gestures, and camera only as needed to realize that request. For speech, animate as if delivering the exact line while keeping mouth movement natural and proportionate. Avoid unrequested redesign, erratic gaze, excessive expression, or malformed hands. Request genuine alpha only when the user wants a transparent overlay; if Muse's alpha capability is unclear, ask before spending credits to test it. If Muse only offers fixed clip lengths, use the nearest documented source duration, then trim, loop, or hold the silent video locally to match the measured narration and requested ending behavior. Ask before changing the narration, speaking pace, or ending choice. Do not silently substitute a solid/chroma-key background for alpha or vice versa.
5. **Generate the voice as a separate asset.** In a distinct audio-generation task, request the exact line in the requested language, accent, voice qualities, tone, emotion, and pace. If these are unspecified, use the narration's language, a clear natural delivery appropriate to the topic, a neutral accent, and no gender assumption. Request a clean audio-only WAV, or MP3 if WAV is unavailable, unless another format was requested; omit music, effects, intro, and outro unless asked. Do not rely on audio embedded in the video. Ask before switching provider or route if Muse cannot provide separate audio.
6. **Use Muse with fewer UI round-trips and wait for both jobs.** Prepare both prompts before interacting. Keep one selected Muse tab/reference and inspect only that page. Batch the video actions (attach the selected image, enter the silent-video prompt, submit), then submit the separate audio task immediately; when the UI supports asynchronous jobs, do not wait for video rendering before submitting audio. Avoid repeated browser-wide inventories, screenshots, and fixed sleeps: inspect state at the start, after submissions, and when checking results; take extra snapshots only for ambiguity or errors. Check both job statuses together and download both assets together. Never refresh, resend, or duplicate a generation. Give a concise update if waiting exceeds a minute. A disconnected/offline label alone is not a blocker if the user explicitly said to use the composer. Stop and ask if Muse requires purchase, upgrade, legal acceptance, new permission, or another unapproved action.
7. **Collect and inspect the separate assets.** Download the video and audio through Muse's visible controls to a temporary review folder; verify they are non-empty. Use `ffprobe` to check duration, dimensions, codecs, audio stream, and alpha when requested. Inspect several frames against the intended background (checkerboard for alpha) and review style, identity, framing, facial/body motion, speech delivery, and artifacts against the user's preferences. Listen to the voice or verify it with a reliable transcript. Do not claim lip-sync, timing, or transparency unless checked. If Muse omitted an asset or returned the wrong background, keep the source and ask before another paid generation or corrective processing.
8. **Combine the requested audio and video locally with FFmpeg.** Probe the narration and use its measured duration as the speaking clip's timeline unless the user explicitly requested another duration. Preserve the complete speech; by default, trim silent video that exceeds the audio; if it is shorter, loop when the seam looks natural, otherwise hold a calm final frame through the remaining speech. Add no outro or extra padding unless requested; never time-stretch the voice or let Muse's default source duration set the final runtime. Apply a requested ending behavior when it differs from this default, and do not force `-shortest` if that would contradict it. For a typical opaque MP4 where looping is acceptable, loop the silent clip and cap the final file at the measured audio duration:

   ```bash
   AUDIO_DURATION=2.35  # replace with the narration duration measured by ffprobe, in seconds
   ffmpeg -stream_loop -1 -i muse-silent.mp4 -i narration.wav \
     -map 0:v:0 -map 1:a:0 -t "$AUDIO_DURATION" \
     -c:v libx264 -pix_fmt yuv420p -c:a aac -b:a 192k \
     -movflags +faststart final.mp4
   ```

   If looping would create a visible seam, use a calm last-frame hold or ask the user how to handle the mismatch. The ProRes 4444 examples below apply only when transparency was requested. Any roughly 0.1-second picture tail is mux-safety headroom only, not user-facing outro or extra runtime. Convert genuine-alpha source to a ProRes 4444 MOV master without flattening alpha (skip this conversion if Muse already returned ProRes 4444):

   ```bash
   ffmpeg -i muse-alpha-video.mov -an -vf format=yuva444p10le -c:v prores_ks -profile:v 4444 -alpha_bits 16 avatar-alpha.mov
   ```

   Verify that `avatar-alpha.mov` still contains transparency. When it is at least as long as the voice track, mux without re-encoding that video stream, for example:

   ```bash
   ffmpeg -i avatar-alpha.mov -i narration.wav \
     -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k \
     -shortest slide-ready-alpha.mov
   ```

   For a non-transparent deliverable, encode/mux in the requested container and codecs. If no compatible format was specified, H.264/AAC MP4 is a practical general-purpose fallback. Test playback in the actual destination app/device when possible. Do not label an ordinary MP4 transparent. If the destination cannot play the requested alpha format, ask which compatible background/export they prefer. [FFmpeg's ProRes documentation](https://ffmpeg.org/ffmpeg-codecs.html#ProRes) describes its 4444 profile and alpha support. PowerPoint lists QuickTime `.mov` as a supported container but recommends H.264/AAC MP4, so test alpha playback in the user's actual slide app and platform before relying on it ([supported formats](https://support.microsoft.com/en-us/powerpoint/video-and-audio-file-formats-supported-in-powerpoint)).
9. **Verify and save the final asset.** Check the combined file has the expected streams, duration, background/alpha behavior, and format; inspect and play it in the target app when available. Save the avatar, separate source audio/video, and final output in a unique ignored folder such as `outputs/muse-<date>-<topic-slug>/`. Keep generated/private media out of commits and label Muse work as external/browser-generated.

### Reusable Muse prompt shape

Use separate concise prompts and keep the actual topic and narration exact:

**Silent video:** Use the attached image as the character reference. Topic: **[topic]**. Requested style, visual mood/palette, framing/aspect ratio, resolution, and frame rate: **[specify]**. Target duration and ending behavior: **[user's explicit choice, otherwise infer from the exact line at requested pace; align final runtime to measured audio]**. Background: **[transparent / solid color / scene / other requested treatment]**. Animate as if saying “**[verbatim line]**” but generate no audio. Apply the requested facial/body motion, expression, gaze, gesture, and camera movement: **[specify]**. Captions/on-screen text: **[exact text or none]**. Preserve identity and avoid unrequested redesign or extra people. Return one silent video file in the requested format.

**Separate audio:** Say exactly in **[language/accent]**: “**[verbatim line]**”, using **[requested voice, tone, emotion, and pace; otherwise a clear natural delivery suited to context]**. Return one clean audio-only **[requested format; otherwise WAV or MP3]**, without music, sound effects, intro, or outro unless requested.

For a series, reuse the same approved avatar image/reference when the user wants identity continuity; change it only when requested or necessary for a genuinely different character/style. Do not regenerate just because narration changes.

## Browser and data boundaries

The Muse route sends the selected image and requested text to an external provider. Only a user request for this ImageGen→Muse workflow authorizes sending the image generated/selected for this run and its narration—not other portraits, voice recordings, credentials, project files, or conversation history. If uploading a local image, identify that exact file and destination. If Chrome's file chooser fails, do not weaken extension permissions or silently substitute an in-chat avatar. Tell the user: “To enable file upload, open `chrome://extensions`, click **Details** under the ChatGPT browser extension, and enable **Allow access to file URLs**.” See the [Chrome file-upload instructions](https://developers.openai.com/codex/app/chrome-extension#upload-files). Never change the permission yourself. Do not accept legal terms, buy credits, or upgrade plans without action-time approval; if the visible cost is not covered by the user's request or included balance, stop and ask.
